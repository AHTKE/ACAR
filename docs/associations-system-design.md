# نظام إدارة الجمعيات المالية — تصميم وهندسة النظام
### (Software Architecture Document — v1.0)

---

## 0. النطاق والهدف

نظام تعاوني شعبي **لليسهم لا للتصدّق**:
- كل عضو يدفع **قسط شهري ثابت** (قيمة السهم).
- حصيلة الشهر كاملة تُقبض لعضو واحد **لديه الدور ذلك الشهر** (تناوب).
- يتبع: بروفايلات، دورة حياة الجمعية، توزيع أدوار، لوحة متابعة شهرية، تنبيهات حالة.

**قاعدة التصميم الحاكمة:** *البيانات الخام تُخزَّن، والحالة تُشتق* — نفس نمط `deriveMember()` الحالي (مسدّد/معلّق/متأخر تُحسب من المدفوع مقابل المطلوب ولا تُكتب يدوياً).

---

## 1. البنية الحالية (نقطة الانطلاق)

| المفتاح | البنية | ملاحظة |
|---|---|---|
| `app_associations` | `{name, fee}` | اسم + اشتراك سنوي فقط |
| `app_members` | `{assoc, name, type, fee, paid, note}` | العضو مربوط بالاسم النصي لا بالشخص |

**الثغرات المطلوب سدها:**
1. لا يوجد «شخص» مستقل → نفس الشخص يتكرر في جمعيتين صفَّين منفصلين.
2. لا يوجد مفهوم **الشهر/الدورة** → `paid` مبلغ تراكمي واحد فقط.
3. لا يوجد **توزيع أدوار القبض** إطلاقاً.
4. لا يوجد سجل زمني (تاريخ مالي) لكل شخص.
5. لا توجد تنبيهات شهرية (من دفع هذا الشهر؟ من تأخّر؟ مَن دوره يقبض؟).

## 2. نموذج البيانات (Data Model)

### 2.1 الشخص — `app_persons` (جديد)
```js
{
  id: 'p_1a2b3c',              // معرّف ثابت (يُولَّد مرة واحدة)
  name: 'أحمد محمد',
  phone: '01013318895',
  note: '...',
  createdAt: '2026-10-29T00:00:00Z',
  history: [                    // السجل المالي/الزمني — append-only
    { date, kind: 'دفعة',  assocId, month: '2026-11', amount: 1000, note: '' },
    { date, kind: 'قبض',   assocId, month: '2026-11', amount: 10000, note: 'دور الشهر' },
    { date, kind: 'ملاحظة', assocId: null, amount: 0, note: 'اتأخر أسبوعين' }
  ]
}
```

### 2.2 الجمعية — تطوير `app_associations`
```js
{
  id: 'a_9f8e7d',
  name: 'جمعية الإعمار',
  shareValue: 1000,        // قيمة السهم الشهري
  months: 10,              // عدد الأسهم/الأشهر في الدورة = عدد الأدوار
  startMonth: '2026-11',   // أول شهر في الدورة (YYYY-MM)
  status: 'نشطة',          // مسودة ← نشطة ← مكتملة ← مغلقة
  members: [               // الأعضاء المشاركون + بداية دورهم
    { personId: 'p_1a2b3c', joinMonth: '2026-11', order: 0 }  // order = ترتيب الدور
  ],
  // → مشتقات (تُحسب لا تُخزَّن):
  // monthlyPot = shareValue × عدد الأعضاء النشطين
  // collectorOf('2026-12') = العضو صاحب order = (index الشهر داخل الدورة)
}
```

### 2.3 دفتر الشهر — `app_assoc_ledger` (جديد)
```js
{
  assocId: 'a_9f8e7d',
  month: '2026-11',
  rows: [
    { personId: 'p_1a2b3c', due: 1000, paid: 1000, paidAt: '2026-11-03' }
    // الحالة تُشتق: paid>=due → مسدّد | paid>0 → معلّق | else → متأخر
  ],
  collectorId: 'p_4d5e6f',  // صاحب الدور هذا الشهر
  collected: false,          // هل تم قبض الحصيلة فعلاً؟
  collectedAt: null,
  payout: 0                  // المدفوع فعلياً (حصيلة الأعضاء الدافعين)
}
```

### 2.4 العلاقات
```
Person 1—* Membership *—1 Association 1—* LedgerMonth 1—* LedgerRow *—1 Person
```

## 3. دورة حياة الجمعية (Lifecycle)

### 3.1 إنشاء (معالج 3 خطوات)
1. **البيانات**: الاسم، قيمة السهم، عدد الأشهر، تاريخ البداية.
   → `الحصيلة الشهرية = قيمة السهم × عدد الأعضاء` (تظهر تلقائياً).
2. **الأعضاء**: اختيار/إضافة أشخاص (من بروفايلات موجودة أو اسم جديد يُنشئ بروفايل).
3. **توزيع الأدوار**: ترتيب الأعضاء (سحب أو أسهم ▲▼) → `order` = رقم الدور، والشهر رقم *n* يخصّ صاحب `order = n mod months`.

### 3.2 الحالات
```
مسودة ──(بدء الدورة)──▶ نشطة ──(اكتمال كل الأدوار)──▶ مكتملة ──▶ مغلقة
   └─(إلغاء)─▶ محذوفة (بتأكيد، ويُنبَّه إن فيها مدفوعات)
```

### 3.3 القواعد المالية
- **حصيلة الشهر** = مجموع ما دفعه الأعضاء *فعلاً* هذا الشهر (لا المطلوب نظرياً).
- **القبض** = تسجيل `collected:true` + ربط بالمقبوض `payout` + إضافة حركة `قبض` في history صاحب الدور.
- **المتأخر**: قسطه يظل في الذمّة ولا يُخصم من صرف صاحب الدور (يُسجَّل كـ «عليه متأخر») — السياسة قابلة للتبديل بخيار في الإعدادات: `صرف كامل المطلوب` مقابل `صرف المقبوض فقط`.
- **دخول/خروج عضو في منتصف الدورة**: يدخل `joinMonth` وتُمنح حصته من الشهر الذي دخل فيه فقط؛ الخروج يوقف الأشهر المتبقية.

## 4. الشاشات (UI Specification)

### 4.1 كارت الجمعية (مطوّر)
الاسم • الأعضاء • `الحصيلة الشهرية` / `قيمة السهم` / `عدد الأشهر` • شريط تقدّم الدورة `الشهر 3 من 10` • حالة الدور الحالي («اليوم دور **وليد صلاح**»).

### 4.2 شاشة الدور/الجدول الشهري (جديد — قلب النظام)
مصفوفة: **الصفوف = الأعضاء، الأعمدة = الأشهر 1..N**
- خلية فارغة ملوّنة = مسدّد (أخضر) / معلّق (أصفر) / متأخر (أحمر)
- رأس العمود: `الشهر + اسم صاحب الدور + زر «تم القبض ✓»`
- النقر على خلية = تسجيل دفعة ذلك الشهر (للمصرَّح فقط)

### 4.3 الداشبورد (لوحة المتابعة)
- **هذا الشهر**: كم دفع / كم متبقٍ / حصيلة مقبوضة؟
- **تنبيهات**: «3 أعضاء متأخرين — أسماؤهم» • «دور أحمد هذا الشهر — لم يقبض بعد»
- **مربّع مَن ينتظر دوره**: ترتيب الأدوار القادمة.
- نفس مربعات الملخّص الأربعة الموجودة (`renderAssocSummary`) لكن مفلترة بالشهر الحالي.

### 4.4 بروفايل الشخص (جديد)
بطاقة: الاسم، الهاتف، حالة الحساب الإجمالي، جدول «جمعياته» (مسدّد/مستحق)، ثم **السجل الزمني** (history) مع زر «إضافة ملاحظة/حركة».
يُفتح من أي صف عضو في أي شاشة.

### 4.5 التنبيهات (Alarms)
```js
statusOf(person, month) → 'مسدّد' | 'معلّق' | 'متأخر' | 'لم يحن'
collectorStatus(month)  → 'تم القبض' | 'بانتظار القبض' | 'لم يحن'
```
تظهر كـ chips ملوّنة في الجدول + شريط في أعلى الداشبورد + (مرحلة قادمة) إشعار داخل التطبيق.

## 5. التكامل مع البنية الموجودة

| الجانب | القرار |
|---|---|
| **التخزين** | localStorage بنفس النمط (`getX/saveX`) + إضافة مفتاحين لمفاتيح المزامنة في `syncKeys` (app.js سطر ~3405) |
| **المزامنة السحابية** | لا تغيير — الحزم الجديدة تدخل نفس snapshot JSON المرفوع للدرايف |
| **الصلاحيات** | المشاهد: عرض الجدول والبروفايلات فقط. المصرَّح: كل العمليات (نفس `auth-gate-addon.js` الحالي) |
| **التصدير** | إضافة خانة «جدول الجمعيات Excel/PDF» لشبكة التصدير الستة الموجودة |
| **التوافق** | Migration عند أول تحميل: `app_members` القديم → `persons` + ledger بأقساط تقريبية، مع الاحتفاظ بالمفاتيح القديمة كنسخة احتياطية |
| **الاختبارات** | إضافة حالات إلى `smoke-test.js` (يضم أصلاً قسمَي [19]-[24] للجمعيات) |

## 6. خطة التنفيذ (Phases)

**المرحلة 1 — النواة (أساس لكل شيء)**
1. طبقة `persons` + دوال `getPersons/savePersons/addHistory`.
2. رفع نموذج `associations` لـ `{id, shareValue, months, startMonth, members[].order}` + migration.
3. توليد ledger للشهر الحالي تلقائياً.

**المرحلة 2 — الأدوار والجدول**
4. معالج إنشاء الجمعية (3 خطوات) + شاشة توزيع الأدوار.
5. المصفوفة الشهرية (أعضاء × أشهر) وتسجيل الدفعات والقبض.

**المرحلة 3 — المتابعة**
6. داشبورد الشهر + التنبيهات + بروفايل الشخص.
7. الاختبارات + التصدير + النشر.

## 7. مثال رقمي مرجعي (يُستخدم في الاختبارات)

- جمعية «الأمل»: سهم **1,000** × **10 أعضاء** = حصيلة شهرية **10,000**
- الأشهر 10، البداية `2026-11`
- `order:0` وليد → دوره نوفمبر (يقبض 10,000)، `order:1` خالد → ديسمبر...
- نوفمبر: 7 دفعوا (7,000)، 3 متأخرين → **payout = 7,000** (سياسة المقبوض) أو 10,000 (سياسة المطلوب)
- الحالة المُشتقّة: 7 «مسدّد»، 0 «معلّق»، 3 «متأخر»
